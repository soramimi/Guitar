# 辞書エディタの開発ガイド

この文書は `dicedit/` 配下を対象とする。
利用方法は [README.md](README.md)、MeCab 本体と辞書生成は [ルートの README.md](../README.md) と [AGENTS.md](../AGENTS.md) を参照する。

## 構成と実行環境

- Go 標準ライブラリの HTTP サーバーと、ライブラリに依存しない JS/CSS/HTML で構成する。
- Go のバージョン指定は `go.mod` の `1.26.1`。
- `main.go` がルーティング、CSV のキャッシュと保存、品詞定義の読み込み、入力検証を担う。
- 画面の挙動は `static/js/app.js`、一覧とモーダルのマークアップは `templates/edit.html`。
- `templates/*.html` と `dicdef/parts-id.def` は `go:embed` で埋め込む。変更後は再ビルド・再起動する。
- JS/CSS は実行時に `static/` から配信する。
- 作業ディレクトリは `dicedit/` を前提とし、CSV は相対パス `../userdic/` から読む。待受は `:2080`。

## データモデルと列の対応

`Record` は画面・API 用の `id` と、CSV の項目をその順序で持つ `fields: string[]` からなる。
レコードの `id` はキャッシュ内の識別子であり、文脈IDや品詞IDではない。CSV には書き出さない。

```text
0 表層形、1 左文脈ID、2 右文脈ID、3 コスト、4 品詞、
5〜7 品詞細分類1〜3、8 活用型、9 活用形、10 原形、11 読み、12 発音
```

`columnNames` と JS の `data-column` を対応させる。
モーダルには絞り込み欄と品詞の select もあるため、全 input の並び順を CSV の列番号に使わない。
既存の追加列（インデックス13以降）も、更新時の配列コピーで保持する。

## 適用と保存の区別

- `getFileData()` は CSV を初回に読み込み、ファイル単位でキャッシュする。
- 追加・編集・削除はキャッシュを変更し、「保存」だけが `saveCSV()` で CSV 全体を書き出す。
- サーバーの終了で未保存の変更は失われる。外部の CSV 変更を自動で再読込する仕組みはない。
- `cacheMu` はキャッシュのマップ、各 `fileData.mu` はレコードを保護する。
- 不正な追加・更新ではキャッシュを変更せず、新しいレコードIDも消費しない。

編集確定の文言は「適用」とし、「保存」は CSV への書き込みに使い分ける。
新規登録の確定ボタンは「追加」。一覧のセルは表示専用にし、編集ボタンは左端、削除ボタンは右端に置く。

## モーダルの動作

- 行の「編集」と画面上部の「行追加」から同じモーダルを使う。
- 新規追加では、モーダルを開いただけで POST したり空行を作ったりしない。
- 「キャンセル」と Esc は、そのモーダルでの未確定入力を破棄する。
- 通信エラーや入力エラーではモーダルを閉じず、入力を保持する。
- 送信中は入力・ボタンを無効化し、Esc による閉鎖と二重送信を防ぐ。
- `close` イベントは遅れて届く場合がある。開き直した後の編集状態を過去の close イベントで消さない。
- 追加後の最終ページ表示、編集後の検索結果の再取得、古い一覧取得の応答の無視を維持する。
- 広い画面は2列、狭い画面は1列にする。項目ラベル、初期フォーカス、エラー表示を保つ。

## 品詞定義と選択

`dicdef/parts-id.def` は UTF-8 の `文脈ID 空白 7項目のCSV` 形式。
7項目は、品詞・細分類1〜3・活用型・活用形・原形区分である。
`parsePartsDefinition()` はIDの範囲・重複・項目数を検証し、`apiParts()` が結果をキャッシュして返す。

現在の1,316件は IPADIC の左右の文脈ID定義に対応する。
選択時は同じIDを左右に設定し、品詞・細分類・活用情報を適用する。
この前提は全ての MeCab 辞書に共通ではないため、別の辞書へ対応する場合は左右の定義を確認する。
ルートの `make dic` は、この定義ファイルも更新する。

JS の選択肢の値は文脈IDであり、CSV の品詞列には定義の品詞文字列を保存する。
細分類・活用情報は読み取り専用表示。文脈ID・コスト・原形・読み・発音は別の入力欄を持つ。
定義末尾の原形区分で CSV の原形を上書きしない。

絞り込みだけでは選択を変更せず、現在選択中の項目は絞り込み対象外でも保持する。
既存値と一致する定義がない場合は `current` の選択肢で元の値を保持する。
別の定義を選んでから `current` に戻した場合も、元の文脈ID・細分類・活用情報へ戻す。
新規追加はリスト選択を必須とし、絞り込み欄の Enter はフォーム確定ではなく select への移動に使う。

## 読み・発音の変換と検証

Go の `normalizeKana()` / `normalizeReadingFields()` と JS の `normalizeKana()` / `submitEditor()` の規則を一致させる。
対象は CSV のインデックス11と12で、POST・PUT のキャッシュ変更前にサーバーでも検証する。

- 一般的なひらがなと繰り返し記号をカタカナへ変換する。
- カタカナ、長音、半角カナ、仮名に続く濁点・半濁点を許可する。
- 半角カナや分解された濁音を、そのまま保持する。NFC/NFKC 正規化は行わない。
- 空欄は許可する。漢字、英数字、空白、句読点、`*`、単独の濁点などは拒否する。
- 読みと発音の両方を確認してから適用し、不正な場合はそのエントリ全体を更新しない。
- 画面ではエラーを表示し、該当欄に `aria-invalid` を付けてフォーカスを移す。

CSV 読み込み時や `/api/save` で、既存レコード全体へ一律の変換・検証を追加する仕様にはなっていない。
規則を変更する場合は Go・JS・テスト・利用者向けの説明をそろえる。

## API

| メソッド・パス | 内容 |
|---|---|
| `GET /api/dics` | 対象ディレクトリの `.csv` ファイル名一覧 |
| `GET /api/parts` | 品詞定義の配列。各項目は `{id, fields}` |
| `GET /api/records?file=...` | 一覧。`q`、`page`、`per_page` を指定可能 |
| `POST /api/records?file=...` | `{fields: [...]}` を追加。成功時は201とレコード |
| `PUT /api/records/{id}?file=...` | `{fields: [...]}` で更新。成功時はレコード |
| `DELETE /api/records/{id}?file=...` | メモリ上のレコードを削除。成功時は204 |
| `POST /api/save?file=...` | キャッシュを CSV へ保存 |

一覧の応答は `columns`、`records`、`total`、`page`、`per_page`、`total_pages` を含む。
画面からは対象ファイルを毎回クエリで明示する。サーバーには Referer から補う既存処理もある。
ファイル名の検証、HTTP メソッドの制限、読み・発音の不正値に対する400応答を維持する。

## ビルドと確認

以下は `dicedit/` で実行する。

```bash
go test ./...
node --check static/js/app.js
go build -o /tmp/dicedit-check .
```

Go の変更は `gofmt` を適用する。文書のみの変更では、リンクと実装・記述の整合性の確認でよい。
`kana_test.go` は仮名の正常・異常系と、POST/PUT の正規化・拒否時のデータ保持を確認する。

UI を変更した場合は、必要に応じて実ブラウザでも次を確認する。

- 編集・追加の適用、キャンセル・Esc、フォーカス、通信エラー時の入力保持。
- 編集・削除ボタンの位置、狭い画面でのモーダル操作。
- 品詞の一致・未一致、絞り込み中の選択保持、IDと細分類の補完、原形・読みの保持。
- ひらがなの変換、非仮名の拒否、読みと発音の両方の検証、API 直接送信時の拒否。
- ページをまたぐ追加、検索結果から外れる編集、CSV保存、追加列の保持。

保存の検証には専用の一時 CSV を使い、実際の `../userdic/` を上書きしない。
HTTP 検証を分離する場合は、一時ディレクトリにモジュール・templates・static・dicdef をそろえ、一時データと別の待受ポートで実行する。
