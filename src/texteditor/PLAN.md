# 修正計画

f5266796(折り返しの二分探索化・X座標の遅延計算)以降のコードレビューで見つかった問題の修正計画。
行番号は変わりやすいため、場所は関数名で示す。

## 方針

- 折り返しの正しさ → キャッシュ整合性と表示上の不具合 → メモリ上限 → 性能 →
  実験機能 → 後片付け、の順に進める
- 折り返しアルゴリズムは Qt 非依存の関数として切り出し、自動テストを先に用意してから修正する
- 各段階でビルドし、既存の動作(1スレッドと並列で折り返し結果が一致すること)を確認する

## 段階1: 折り返しの正しさ(最優先)

### 1-1. 折り返しアルゴリズムの切り出しとテスト整備(完了)

`_wrap_line()` の段階1(分割候補の列挙)と段階2(終端位置の決定)を、Qt に依存しない
`WrapAlgorithm.h/.cpp` へ切り出した。

```cpp
// 例: 文字列は char32_t 列、幅の計測はコールバックで受け取る
std::vector<size_t> texteditor::wrap_algorithm::compute_wrap_points(
	std::u32string_view text, int width_px, Mode mode, Measure const &measure);
```

- `_wrap_line()` はこの関数を呼び、戻り値の区切り位置から断片を組み立てる
- `WrapAlgorithm/` にQt非依存のGoogleTestを追加した
  - 毎回全探索する貪欲法の参照実装と5,000件のランダム入力を比較する
  - 空文字列、幅0、CharWrap、WordWrapへの切り替え、長い単語を固定テストする
  - 確認する性質:
    - 断片を連結すると元の文字列に戻る
    - 幅を超える断片は「WordWrap切り替え後の1単語、またはCharWrapの1文字」の場合に限る
    - 各断片は幅に収まる範囲でできるだけ長い
- WordWrapの仕様は現実装を維持する:
  - 論理行の先頭はCharWrap状態で開始する
  - 最初の分割可能位置に到達した後はWordWrapへ切り替え、論理行末まで戻さない
  - 切り替え後の1単語が表示幅を超える場合は、文字分割せず幅超過を許容する
- 以下のケースを固定テストへ追加した(幅はいずれも1文字=1)

| 入力 | 幅 | 修正前の結果 | 期待値 |
|---|---|---|---|
| `"ab cdefghij kl mn op"` | 5 | `["ab ", "cdefghij kl mn op"]` | `["ab ", "cdefghij ", "kl ", "mn op"]` |
| `"aa bbbbbbbbbbbbbbbb cc"` | 6 | 2行目以降がまとめられる | `["aa ", "bbbbbbbbbbbbbbbb ", "cc"]` |
| `"abcdefghij"` | 4 | 行末まで分割可能位置がない | `["abcd", "efgh", "ij"]` |

### 1-2. 残りの文字列がまとめて1行になる不具合(完了)

**原因**: 二分探索が最後の1要素で「収まる」と確定したとき、`index = lo` が採用した候補そのもの
(`points[lo] == a.pos`)を指す。次回の探索で先頭の候補が幅0の空文字列になり、次の単語が幅を
超えると空文字列が採用される。その結果 `a.pos == last_pos` となり、`else` 分岐が残り全体を
1行として出力して終了する。

**修正**:
- 採用した候補の次を、次回探索の先頭として明示的に保持する
- 最初の候補が幅を超える場合もその候補を採用し、最低1文字または1単語進める
- 各終端が開始位置より大きく、文字列長以下で、最後の終端が文字列長になることを保証する
- 残り全体を出力して異常を隠すフォールバックを廃止する

### 1-3. WordWrapにおける長い単語の仕様(対応不要・仕様確定)

現実装を仕様とする。CharWrap状態は論理行の先頭だけに適用し、最初の分割可能位置から
WordWrapへ切り替えた後は、表示行が変わってもCharWrapへ戻さない。したがって後続する長い単語は
文字単位に分割せず、単語終端までを1表示行として幅超過を許容する。

## 段階2: 折り返しの性能

### 2-1. 長い行で計測量が行長の二乗になる問題(完了)

**原因**: 二分探索の最初の候補が残り全体の中央なので、1回目の計測で残りの半分の長さを測る。
表示行が S 行ある場合、計測する文字数の合計はおよそ N×S/2 になる。

**修正**: 指数探索(ギャロッピング)へ変更した。
1. 開始位置から候補を 1, 2, 4, 8… 個先と倍々に計測し、幅を超えた時点で止める
2. 最後に収まった候補と超えた候補の間で二分探索する

幅を超える近傍を見つけてからその区間だけを二分探索するため、残り全体の中央を表示行ごとに
計測しなくなった。4,000文字を40文字幅で分割するテストでは、計測対象コードポイント数の合計が
入力長の12倍未満になることを常設テストで確認する。これは実時間ではなく計測量を検査するため、
実行環境に左右されず二乗化の再発を検出できる。

### 2-2. 部分文字列の組み立てコスト(完了)

**現状**: `ucs4cache` が1文字ごとに `QString` を確保し、計測のたびに連結している。

**修正**: `Utf16Text` が論理行を最初に1回だけ `QString` へ変換し、
コードポイント位置 → UTF-16オフセットの配列を作る。計測は `mid()` で切り出した文字列で行う。
BMP外文字を含む `A😀B` の全部分範囲を常設テストで確認する。

### 2-3. 並列折り返しの検証(完了)

`setLayoutThreadCount()` を追加し、既定値を8、0指定を1として扱う。実際の
`AbstractTextEditorApplication` にASCII、長い単語、タブ、日本語、BMP外文字を含む256論理行を
読み込ませ、1スレッドと8スレッドで次の完全一致を常設テストにした。

- 全折り返し断片のUTF-8文字列
- 論理行ごとの折り返し数
- 全論理列の `logical_to_visual()` 結果
- 全表示行の `visual_to_logical()` 結果
- 論理行数・表示行数と `LineIndexMap::validate()`

同テストはThreadSanitizerビルドでも警告なしで成功した。実際のスレッド数は論理行数を上限とし、
空文書や小さい文書で不要なワーカースレッドを生成しない。

## 段階3: 幅キャッシュとX座標キャッシュ

### 3-1. `text_width_cache_` が際限なく増える問題(完了)

**現状**: 二分探索の計測文字列と、`CharBuffer::left_x()` の行頭からの部分文字列がすべてキーとして
保存され、フォント変更時にしか消えない。

**修正**:
- 最大4,096件のLRUとし、参照された項目を最新位置へ移動する
- 64 UTF-16コード単位を超える文字列は登録せず、1件の巨大なキーによるメモリ占有を防ぐ
- フォントまたはタブ幅の変更時は、LRU本体と索引を同時に全消去する
- `TextEditorCoreTest/` でLRU順の更新、最古項目の削除、長いキーの非登録をテストする

3-2でX座標を一括計算する際には幅キャッシュの利用頻度が下がる見込みだが、短い異なる文字列も
増え得るため、LRUの上限は維持する。

### 3-2. `left_x()` / `right_x()` の計算量

**現状**: 未計算の位置ごとに行頭からの部分文字列を組み立てて計測するため、1行の全位置を求めると
二乗の計算量になる。NoWrap で長い行を描画するときに特に重い。

**修正**:
- 未計算の位置が要求されたら、その断片の全文字のX座標を `QTextLayout` の `cursorToX()` などで
  一括計算し、各 `Character` に格納する
- 描画(`drawText`)との幅のずれがないことを、タブ・カーニング・結合文字を含む行で目視確認する

### 3-3. 行末のX座標がキャッシュから読まれない問題

**原因**: `right_x(size-1)` は `left_x(size)` を呼ぶが、`pos == size` の位置には `Character` が
ないため毎回再計算になる。書き込んだ `_right_x_` は読まれていない。

**修正**: `left_x()` で `pos == size` のときは `(*vec)[pos - 1].right_x()` を参照する。
3-2 を実施する場合はそちらに含める。

## 段階4: その他の不具合

### 4-1. 文字色がテーマを無視する(Dark テーマで本文が黒くなる)(完了)

**原因**: `CharAttr::color` の既定値 0 が「黒」として扱われ、`textColor()` がそのまま使っている。

**修正**:
- `CharAttr::flags` に「前景色指定あり」のビットを追加した
- `textColor()` / `colorForIndex()` は、ビットが立っていなければ `defaultForegroundColor()` を使う
- ANSIの黒(色値0)と色指定なしを区別し、SGR 0は明示色状態を解除する
- `TextEditorCoreTest/` で既定色と明示的な黒の区別、SGR 0による解除をテストする

### 4-2. タブ幅の変更で幅キャッシュが失効しない(完了)

**修正**: `Font::set_tab_stop_distance()` で値が変わった場合に `text_width_cache_` を消去する。
(`update_font()` は既に `metrics_revision` を進めているので、行の解析結果は失効する)
同じ値を再設定した場合はキャッシュを維持するテストも追加した。

### 4-3. `update_font()` の `initEditor()` 前呼び出し

**修正**: `Q_ASSERT(editor_cx)` に加えて、`editor_cx` が null なら早期 return する。
`initEditor()` の最後で `update_font()` を呼び、タブ幅を確定させる。

## 段階5: ターミナルモード(実験機能)

### 5-1. 折り返すと色が消える

**原因**: 断片はエスケープシーケンスを取り除いた文字から UTF-8 を作り直しているため、断片を
再解析すると色情報が失われる。

**修正**: `_wrap_line()` で断片の `Line` を作るとき、`chrs_out` の文字列(属性つき)を断片の
`LineProperty` に入れ、`text_revision` / `metrics_revision` を設定しておく。断片の再解析も
不要になる。根本的には AGENTS.md の既知課題「断片を元論理行の範囲参照にする」で解決する。

### 5-2. エスケープシーケンスの状態が次の行へ引き継がれない

行ごとの解析キャッシュと並列折り返しの前提(各行が独立して解析できる)に反するため、今回は
対応しない。必要になった場合は、各行の行頭時点の色状態を `Meta` に保持する設計を別途検討する。

### 5-3. `EscapeSequence` の解釈漏れ

- `ESC[m`(引数なし)をリセットとして扱う(現在は `chars_.size() > 2` の条件で無視される)
- `ESC[1;31m` のような複数引数の SGR で、全引数を順に処理する
