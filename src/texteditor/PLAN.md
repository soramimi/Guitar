# 修正計画

f5266796(折り返しの二分探索化・X座標の遅延計算)以降のコードレビューで見つかった問題の修正計画。
行番号は変わりやすいため、場所は関数名で示す。

## 方針

- 折り返しの正しさ → 性能 → その他の不具合 → 後片付け、の順に進める
- 折り返しアルゴリズムは Qt 非依存の関数として切り出し、自動テストを先に用意してから修正する
- 各段階でビルドし、既存の動作(1スレッドと並列で折り返し結果が一致すること)を確認する

---

## 段階1: 折り返しの正しさ(最優先)

### 1-1. 折り返しアルゴリズムの切り出しとテスト整備

`_wrap_line()` の段階1(分割候補の列挙)と段階2(終端位置の決定)を、Qt に依存しない関数として
切り出す。

```cpp
// 例: 文字列は char32_t 列、幅の計測はコールバックで受け取る
std::vector<size_t> compute_wrap_points(
	std::u32string_view text, int width_px, WrappingMode mode,
	std::function<int(size_t from, size_t to)> const &measure);
```

- `_wrap_line()` はこの関数を呼び、戻り値の区切り位置から断片を組み立てるだけにする
- テストは LineIndexMap と同じく GoogleTest で書く(`WrapAlgorithm/` などの独立ディレクトリ)
  - 1文字=1幅の計測関数を使い、毎回全探索する貪欲法の参照実装とランダムに比較する
  - 確認する性質:
    - 断片を連結すると元の文字列に戻る
    - 幅を超える断片は「1単語(WordWrap)または1文字(CharWrap)だけ」の場合に限る
    - 各断片は幅に収まる範囲でできるだけ長い
- 以下の再現ケースを固定テストとして入れる(幅はいずれも 1文字=1)

| 入力 | 幅 | 現状の結果 | 期待値 |
|---|---|---|---|
| `"ab cdefghij kl mn op"` | 5 | `["ab ", "cdefghij kl mn op"]` | `["ab ", "cdefg", "hij ", "kl ", "mn op"]`(1-3 で長い単語を分割する場合) |
| `"aa bbbbbbbbbbbbbbbb cc"` | 6 | 2行目が17文字で幅を超える | 長い単語は文字単位で分割される |

### 1-2. 残りの文字列がまとめて1行になる不具合

**原因**: 二分探索が最後の1要素で「収まる」と確定したとき、`index = lo` が採用した候補そのもの
(`points[lo] == a.pos`)を指す。次回の探索で先頭の候補が幅0の空文字列になり、次の単語が幅を
超えると空文字列が採用される。その結果 `a.pos == last_pos` となり、`else` 分岐が残り全体を
1行として出力して終了する。

**修正**:
- 次回の探索開始位置は「`a.pos` より大きい最初の候補」とする
  (`std::upper_bound(points.begin(), points.end(), a.pos)`)
- `else` 分岐(先へ進めなかった場合の残り全体出力)は廃止し、ループの終了条件を
  `last_pos == N` で明示する
- 先へ進めない状況が構造上起きないことを `Q_ASSERT(a.pos > last_pos)` で確認する

### 1-3. 長い単語が論理行の先頭でしか分割されない不具合

**原因**: 段階1で「最初の単語境界までは文字単位の候補を作る」処理を、論理行の先頭で1回だけ
行っている。旧実装は表示行ごとに文字単位へ戻していた。

**修正**:
- 段階1は純粋に `wrappingMode()` に従った候補だけを列挙する(先頭の特別扱いは削除)
- 段階2で、開始位置の直後の候補だけで幅を超える(=単語が表示幅より長い)場合、その区間
  `[curr_pos, 次の候補)` の中で文字単位の二分探索を行い、収まる最長位置で分割する
- 1文字でも幅を超える場合は1文字を出力して必ず前進させる

## 段階2: 折り返しの性能

### 2-1. 長い行で計測量が行長の二乗になる問題

**原因**: 二分探索の最初の候補が残り全体の中央なので、1回目の計測で残りの半分の長さを測る。
表示行が S 行ある場合、計測する文字数の合計はおよそ N×S/2 になる。

**修正**: 指数探索(ギャロッピング)に変える。
1. 開始位置から候補を 1, 2, 4, 8… 個先と倍々に計測し、幅を超えた時点で止める
2. 最後に収まった候補と超えた候補の間で二分探索する

計測する文字列の長さが表示行の長さの約2倍までに抑えられ、行全体の計算量はほぼ線形になる。

### 2-2. 部分文字列の組み立てコスト

**現状**: `ucs4cache` が1文字ごとに `QString` を確保し、計測のたびに連結している。

**修正**: 論理行を最初に1回だけ `QString` へ変換し、文字インデックス → UTF-16 オフセットの
配列(サロゲートペア対応)を作る。計測は `mid()` で切り出した文字列で行う。

### 2-3. 並列折り返しの有効化

段階1と段階2が終わった時点で `update_visual_lines_all()` の `NUM_THREADS` を 8 にする。
大きなファイルで所要時間を測り、1スレッドの場合と折り返し結果が一致することを確認する
(ThreadSanitizer ビルドでの確認手順は前回と同じ)。

## 段階3: 幅キャッシュとX座標キャッシュ

### 3-1. `text_width_cache_` が際限なく増える問題

**現状**: 二分探索の計測文字列と、`CharBuffer::left_x()` の行頭からの部分文字列がすべてキーとして
保存され、フォント変更時にしか消えない。

**修正案**(要判断):
- A. 一定の長さ(例: 64文字)を超える文字列はキャッシュに入れない
- B. 件数上限つきのLRUにする
- C. `left_x()` の計算を、下記 3-2 の一括計算に置き換え、キャッシュの用途を短い文字列の計測に限定する

**推奨**: C を基本とし、A を併用する。

### 3-2. `left_x()` / `right_x()` の計算量

**現状**: 未計算の位置ごとに行頭からの部分文字列を組み立てて計測するため、1行の全位置を求めると
二乗の計算量になる。NoWrap で長い行を描画するときに特に重い。

**修正**:
- 未計算の位置が要求されたら、その断片の全文字のX座標を `QTextLayout` の `cursorToX()` などで
  一括計算し、各 `Character` に格納する
- 描画(`drawText`)との幅のずれがないことを、タブ・カーニング・結合文字を含む行で目視確認する

### 3-3. 行末のX座標がキャッシュから読まれない問題

**原因**: `right_x(size-1)` は `left_x(size)` を呼ぶが、`pos == size` の位置には `Character` が
ないため毎回再計算になる。書き込んだ `_right_x_` は読まれていない。

**修正**: `left_x()` で `pos == size` のときは `(*vec)[pos - 1].right_x()` を参照する。
3-2 を実施する場合はそちらに含める。

## 段階4: その他の不具合

### 4-1. 文字色がテーマを無視する(Dark テーマで本文が黒くなる)

**原因**: `CharAttr::color` の既定値 0 が「黒」として扱われ、`textColor()` がそのまま使っている。

**修正**:
- `CharAttr::flags` に「色指定あり」のビットを追加する
- `textColor()` / `colorForIndex()` は、ビットが立っていなければ `defaultForegroundColor()` を使う
- `EscapeSequence` のリセット(SGR 0)はビットを落とす扱いにする

### 4-2. タブ幅の変更で幅キャッシュが失効しない

**修正**: `Font::set_tab_stop_distance()` で値が変わった場合に `text_width_cache_` を消去する。
(`update_font()` は既に `metrics_revision` を進めているので、行の解析結果は失効する)

### 4-3. `update_font()` の `initEditor()` 前呼び出し

**修正**: `Q_ASSERT(editor_cx)` に加えて、`editor_cx` が null なら早期 return する。
`initEditor()` の最後で `update_font()` を呼び、タブ幅を確定させる。

## 段階5: ターミナルモード(実験機能)

### 5-1. 折り返すと色が消える

**原因**: 断片はエスケープシーケンスを取り除いた文字から UTF-8 を作り直しているため、断片を
再解析すると色情報が失われる。

**修正**: `_wrap_line()` で断片の `Line` を作るとき、`chrs_out` の文字列(属性つき)を断片の
`LineProperty` に入れ、`text_revision` / `metrics_revision` を設定しておく。断片の再解析も
不要になる。根本的には AGENTS.md の既知課題「断片を元論理行の範囲参照にする」で解決する。

### 5-2. エスケープシーケンスの状態が次の行へ引き継がれない

行ごとの解析キャッシュと並列折り返しの前提(各行が独立して解析できる)に反するため、今回は
対応しない。必要になった場合は、各行の行頭時点の色状態を `Meta` に保持する設計を別途検討する。

### 5-3. `EscapeSequence` の解釈漏れ

- `ESC[m`(引数なし)をリセットとして扱う(現在は `chars_.size() > 2` の条件で無視される)
- `ESC[1;31m` のような複数引数の SGR で、全引数を順に処理する
